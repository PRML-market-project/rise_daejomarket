# 대조시장 키오스크 검색 검증

검증일: 2026-11-03 (한국 시간)

## 데이터와 검증 범위

- 지도 원본 `frontend/ml-test-main/src/data/figma-map-shops.ts`의 **126개 점포 전체**를 사용했다.
- 관리자 API(8080)에 연결되지 않아 상세 설명·키워드·태그는 로컬에 저장된 `artifacts/shop-descriptions/shops-applied.json`의 126개 점포 스냅샷을 사용했다. 운영 DB의 최신 상태를 검증했다는 의미는 아니다.
- 설명 중 자동으로 작성된 초안도 있어, 설명을 현재 재고·영업 여부·알레르기 안전성의 증거로 사용하지 않는다.
- 실제 로컬 Gemma 모델에 질의했다. 유료 API 폴백과 관리자 데이터 변경은 하지 않았다.
- 전체 응답 함수 검증은 의도를 지정하고, 별도 `/gpt` 검증은 실제 의도 분류·언어 선택·Flask 라우트까지 실행한다. 음성 인식과 물리 키오스크의 수동 조작은 이번 검증 범위에 포함하지 않았다.

공통으로 유효한 JSON, 중복·허구 ID 제거, 85자 이하의 안내 문구, 요청 개수, 관련 점포 범위와 필수 점포를 확인한다. 안내 문구는 필수/금지 표현을 검사하고 실제 응답 원문도 저장한다. 이 검사는 모든 자연어 표현의 의미를 완벽하게 판정하는 장치는 아니다.

업종은 실제 취급 상품과 다를 수 있다. 닭강정·곱창·족발 등이 정육으로 분류되어 있어 식사 대안은 이름·설명도 보고 인정한다. 반대로 미용실은 식사 대안으로 인정하지 않는다. 분포를 맞추려고 무관한 점포를 끼워 넣지 않는다.

## 수정한 동작

1. 일반 검색의 18개 후보 제한과 프런트 태그 검색의 12개 제한을 제거했다. 뒤쪽 점포도 페이지를 넘겨 선택할 수 있다.
2. 조건 없는 업종 질문은 서버에서 전체 일치 점포를 유지한다. LLM이 목록 일부를 빠뜨려도 보완한다. 상품·식단·제외·개수 조건이 있으면 전체 업종으로 강제 확장하지 않는다.
3. 응답마다 카드 순서를 섞는다. 태그 검색도 새 선택마다 다시 섞고, 페이지 이동 중에는 순서를 유지한다. 거리 정렬을 사용자가 선택하면 거리순으로 표시한다.
4. 상황 추천은 전체 후보의 설명과 새 키워드를 참고한다. 이름·설명과 중복되는 색인 값은 줄여 문맥을 절약한다. 문구 사이를 붙여 생기는 잘못된 검색 매치도 방지한다.
5. 음식 대안에서 잡화·서비스업을 제외하고, 명시한 제외 업종과 긍정 조건으로 후보를 좁힌다. 음식과 의류 등을 함께 요청한 경우는 별도로 판단한다.
6. 기존의 비 오는 날 따뜻한 음식 안내 4개 점포는 조건 없는 해당 질문에서 누락을 보완한다. 한 곳만·채식·제외 등의 조건이 붙으면 강제 추가하지 않는다. 특정 점포를 고정 순위로 우대하지 않는다.
7. 없는 상품은 등록 정보에서 확인되지 않았다고 설명하고 관련 점포를 문의 대상으로 제안한다. 주문·결제·예약·배달은 처리 완료로 말하지 않고 직접 문의를 안내한다. 무관한 질문에는 시장 점포·길 안내라는 범위를 알린다.
8. 음식 추천을 메뉴 조회로 잘못 분류하지 않도록 의도 프롬프트를 수정했다. 범위 밖 질문이나 분류 실패를 총액 질문으로 처리하지 않는다.
9. 길게 반복되다가 잘린 JSON은 완성된 안내 문구와 완성된 카드만 복구한다. 미완성 ID는 버리고 현재 후보 검증·중복 제거를 다시 거친다. 문구나 완성된 카드가 없으면 정상 응답으로 꾸미지 않는다.
10. 로컬 모델은 `--parallel 1`로 실행한다. 반복 실행에서 동시 슬롯의 문맥 메모리 초과가 발생해 요청을 순차 처리하도록 했다.

프롬프트 원문: [kiosk_search_prompt.txt](../ai-server/code/kiosk_search_prompt.txt)

## 노출 순서와 분포

7개 업종마다 서버의 실제 결과 보정·셔플을 1,000회 실행했다. 이 7,000회는 LLM을 매번 호출한 횟수가 아니라 **결과 배열 처리 검증 횟수**다. 시드 20261103을 사용했고, 매번 같은 업종의 전체 점포 집합이 유지되는지도 확인했다.

| 업종 | 점포 수 | 1,000회 중 첫 화면 노출 최소–최대 | 서로 다른 전체 순서 | 미노출 점포 |
| --- | ---: | ---: | ---: | ---: |
| 서비스업 | 2 | 1000–1000 | 2 | 0 |
| 수산 | 10 | 574–624 | 1000 | 0 |
| 식당 | 10 | 561–633 | 1000 | 0 |
| 식품 | 62 | 83–113 | 1000 | 0 |
| 잡화 | 12 | 483–517 | 1000 | 0 |
| 정육 | 17 | 325–366 | 1000 | 0 |
| 청과 | 13 | 441–493 | 1000 | 0 |

첫 화면은 6개 카드다. 업종별 점포 수가 다르므로 서로 다른 업종의 횟수를 같게 만드는 대신, **같은 질문에 적합한 점포 집합 안에서** 비교했다. 순서를 섞으면 확률적으로 고르게 노출되며, 매 요청의 첫 점포가 반드시 직전과 달라지거나 횟수가 완전히 같아진다는 보장은 아니다. 두 점포뿐인 서비스업은 가능한 순서 자체가 2개다.

점포별 직접 질문 수, 전체 노출 횟수, 업종 질문에서의 첫 화면 노출 횟수는 [kiosk-search-exposure.json](./kiosk-search-exposure.json)에 있다.

## 다시 실행하기

저장소 루트에서 로컬 모델을 실행한다. `run-all.ps1`에도 같은 순차 처리 옵션을 반영했다.

```powershell
ai-server/.llama-cpp/llama-server.exe -m ai-server/gemma-4-26B_q4_0-it.gguf --host 127.0.0.1 --port 8010 -ngl all -c 8192 --parallel 1 -b 256 -ub 256 -t 12 --reasoning off --jinja --no-webui
```

모델의 `/health`가 준비된 다음 별도 터미널에서 실행한다. 운영 관리자 데이터를 검증하려면 API가 실행 중일 때 새 스냅샷을 먼저 받는다.

```powershell
Invoke-WebRequest http://127.0.0.1:8080/api/kiosk-experience -OutFile artifacts/kiosk-experience.json
python -X utf8 ai-server/code/evaluate_kiosk_search.py --mode local --experience artifacts/kiosk-experience.json
ai-server/.venv/Scripts/python.exe -X utf8 ai-server/code/smoke_kiosk_endpoint.py --experience artifacts/kiosk-experience.json
```

이번과 동일한 저장 스냅샷을 쓸 때는 `--experience artifacts/shop-descriptions/shops-applied.json`을 지정한다. `--experience`를 생략하면 지도 원본만 사용한다. 스냅샷과 모델 파일은 Git에 포함하지 않는다.

```powershell
python -X utf8 -m unittest discover -s ai-server/code -p test_kiosk_search*.py -v
python -X utf8 ai-server/code/evaluate_kiosk_search.py --mode offline
```

`offline`은 모델 대신 의도적으로 일부 결과를 누락시키는 스텁으로 검색·보정만 검사한다. 자연어 응답 품질의 성공률로 사용하면 안 된다. 모델 실행 결과는 `artifacts/kiosk-search-evaluation/`에 질문, 원문 응답, 사용 토큰, 처리 시간, 실패 사유와 노출 통계로 저장된다.

프런트 검증은 `frontend/ml-test-main`에서 실행한다.

```powershell
node scripts/test-search-exposure.mjs
node scripts/test-kiosk-ai-message.mjs
node scripts/test-category-chips.mjs
node scripts/test-result-map-overview.mjs
npm.cmd run build
```

일반 질문·예외 안내의 대표 실제 응답은 [kiosk-search-response-examples.json](./kiosk-search-response-examples.json)에 있다. 결과는 이번 카탈로그·스냅샷·모델을 기준으로 하므로 관리자 데이터나 모델이 바뀌면 다시 실행해야 한다.
